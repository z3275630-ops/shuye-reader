# 按症状排查

先核对版本，再查原因；同一个症状可能有多个来源，不能仅凭表格断定。下面区分已经修复的历史问题、源码确认的缺口与尚待复现的后果。功能范围见 [功能对照](report-coverage.md)，本版证据见 [0.3.9 验证](verification-0.3.9.md)。本表参考协助 PR #54，经主 Agent 校正，不照搬所有“真因”断言。

## 界面、日期与统计

| 症状 | 定位与当前状态 |
| --- | --- |
| 设置看起来字太大 | 先检查系统字号与设置 → 外观中的倍率。旧阅读控制图为 320dp / 150% 压力图；0.3.9 标题 20dp、控件 15dp，系统非线性缩放逐字号保留。默认预览是 390dp / 100%，`-large` 是压力图。 |
| 日期跨夏令时偏一天 | 历史 #4 已采用自然日构造；不要用减 24 小时推算日历日期。新七天图同样按自然日构造，有跨年 / 闰日回归。 |
| 夜读选中文字或手柄看不清 | #37 已按实际纸色派生选择范围与手柄；自定义正文 / 纸色本身若低对比度，仍需用户调整。不要删除主题 brightness 设置：当前 Flutter copyWith 会更新 ColorScheme。 |
| 320dp 大字下页码挤出屏幕 | #38 已给页码 / 百分比宽度约束并允许换行，按钮至少 48dp；测试覆盖 1.5 / 2.25 倍。其他入口不因这一项修复而自动视为无溢出。 |
| 快速连点打开两个阅读页 | #39 已保护加载与首帧；之后允许桌面链接打开另一书，底下的正文 / PDF 阅读页暂停计时。 |
| 切 Tab 后书架像少了书 | #40 已让输入框与过滤词共用持久 controller；清除可见查询后恢复列表。 |
| 翻页像整屏刷白 | 先核对翻页模式、纸色和当前版本。#20 已分开实现平移与淡入；此前“白色 RGB 导致白色染色”的推断未成立，不作为已确认原因。 |
| 统计累计与日历不一致 | #53 待修：restore 只检查日期字符串形状，手工损坏备份可含不存在的日期；汇总含全部已存日期，热力图限制范围且排除未来。系统时钟提前会产生未来日期，不能解释二月三十一日。 |

## 书库、备份与导入

| 症状 | 定位与当前状态 |
| --- | --- |
| 升级书库时反复失败 | #2 / #34 待修：单本迁移失败与整库快照超过 restore 80 MB 门槛是不同路径。失败保留旧库，不能承诺当前已有可操作的恢复入口；本版未改 Android 加密迁移。 |
| 迁移恢复文件长期占空间 | #50 待修：`repository.dart` 写入加密恢复快照，目前未找到应用读取 / 清理入口。与 #7 的恢复点流程一起设计，不能无条件删掉可能需要的恢复材料。 |
| 恢复后设置又变旧 | #51 待修：同步服务正确保存恢复设置，工具箱内仍持有旧 ReaderSettings；工具箱关闭后主页面才 reload。应统一恢复路径的内存与主题刷新。 |
| 备份少了未保存的阅读时间 | #52 待修：backup / restore 未接阅读计时重试队列。恢复后旧队列对新书库的影响尚待回归，不作为已复现设备结论；单加 flush 也不等于已覆盖阅读页尚未提交的秒数。 |
| 设置损坏后首页空白 | #3 待修：读取设置失败与书籍真的丢失须区分；恢复体验应保留原书库，不能直接清库。 |
| 文本导入变乱码 | #35 待修：严格 UTF-8 失败后整本按 GBK。PR #42 的低错误率修复也会损坏合法 GBK，详见衔接表；计划保留来源并让编码可确认。 |
| EPUB 书名或正文含替换字符 | #46 待修：EPUB 的 read 无条件宽松 UTF-8，未处理 XML 编码声明。非 UTF-8 输入会静默损坏；不要据此宣称所有 GBK EPUB 都符合规范或一律猜编码导入。 |
| 中文 RTF 成为拉丁字符 | #48 待修：十六进制转义逐字节转字符，缺少 ansicpg 与字节序列解码。需保留 Unicode 控制字语义，不能简单规定所有文件缺省 GBK。 |
| EPUB 缺一章整本导入失败 | #47 待核定容错方式：缺失 spine 文件会让 read 抛错，这是源码现状。静默跳章会产生不完整书籍，需可见缺失清单 / 用户确认；大小写兜底也要处理歧义。 |
| 自定义分章 / 净化后卡住 | #49 待修：现校验限制括号，多个无括号重复片段仍可通过。Dart 回溯正则无内置超时，需安全语法或可中断执行；不要在主线程尝试长恶意输入。 |
| ZIP / CBZ / EPUB 内存突增 | #33 待修：当前展开上限来自可伪造声明大小。锁定 archive 的 IO inflate 先汇总输出，再交 OutputStream，单加预算流不能限制此前分配。需真正逐块限额 / 校验。 |
| 大书导入或备份慢 | #18 待修：PDF / CBZ 等资源及整库快照存在完整内存复制；APK 变小不能证明峰值内存下降。 |

## 构建与验证

| 症状 | 定位与当前状态 |
| --- | --- |
| 可选截图被跳过 | 需要 `SHUYE_CAPTURE_DIR` 和字体路径，见 [预览说明](ui-design.md)。预览是电脑 Flutter 渲染，不能当手机性能证据。 |
| Windows 中文路径编译失败 | 本机曾遇到 Kotlin / Flutter tester 临时路径问题；先按 [构建说明](windows-build.md) 用独立英文工作副本 / TEMP，不能泛称所有失败都是着色器崩溃。 |
| Flutter 正等待锁 | 多 Agent 共享 SDK / 缓存的正常争用可能造成等待；项目、副本和 TEMP 分开，不清锁、升级共享 SDK 或杀其他 Agent 的进程。 |
| APK 比以前大 | 查 release 实测体积与 ZIP 资源差异；0.3.8 增加字体，0.3.9 静态资源不变，仅代码等变化。不能把“没有新资源”说成包体绝对零增长。 |
