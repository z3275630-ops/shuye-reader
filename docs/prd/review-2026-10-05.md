### 追加到达的 DeepSeek 审查：PR #41 / Issue #33–#40

在第一轮外观验证后收到 [PR #41](https://github.com/z3275630-ops/shuye-reader/pull/41)，基线为 0.3.8。它未跑 Flutter 测试和 Android 构建，故不能把静态分析结论当作发布验证。主 Agent 将修改应用到当前 main，补充实际回归后重新构建正式包。

- **#36 / #39 / #40 与 PR #41 采纳**：统计说明改为“不足 5 秒的有效记录也计入”，不更改历史统计口径；打开书籍在加载与新页面首帧期间防重入，之后允许桌面深链接打开其他书，不能一直锁到返回；两个搜索框持有独立 controller 并释放，切 Tab 后文本与过滤条件一致。另在正文与 PDF 原计时器检查路由是否当前，覆盖页面不计阅读时长；加载 / 导航失败在 finally 解除守卫，返回刷新不解锁其他正在进行的打开请求；补慢加载连点、返回再次打开、阅读中另一本深链接与覆盖计时回归。
- **#37 采纳问题、调整建议**：按实际纸色和正文色派生正文选中背景，陶土手柄不足 3:1 时回退可读文字色 / 黑白；六套纸色的选中区域文字达到 4.5:1，手柄与纸面达到 3:1。半透明范围底色不能机械套用“底色对比 3:1”，否则部分夜读纸色会让文字不再可读；夜读范围底色以可见性与文字清晰度一起验证。提案中“copyWith(brightness:) 无效”的附加说法不成立：当前 Flutter theme_data.dart:1641 明确更新 colorScheme.brightness，不为此重写整套阅读主题。
- **#38 采纳**：实际阅读页脚抽为共用 ReaderFooter，页码与百分比有明确宽度约束，可自然换行；三个按钮仍保留 48dp 触控尺寸。补实际字体、320dp、三位数页码、1.5 与 2.25 倍字号的检查，不用缩小点击区域解决溢出。
- **#33 认可风险、保留优先修复**：锁定 archive 4.3.0 的 ZIP 大小确实来自元数据，verify 的 CRC 块被注释；现有上限不能证明实际输出受限。但仅套有上限 OutputStream 也不足以修复：本机 `_zlib_decoder_io.dart` 使用 withCallback 的 ChunkedConversionSink，在关闭时才把已收集输出送给流，预算异常可能发生在大内存分配后。后续必须实现真正逐块限额的解压并验证伪造大小、CRC、逐文件失败和 EPUB/CBZ；不将未完成的流式限制宣传为已解决。
- **#34 认可风险、保留优先修复**：内部迁移调用 restore，继承 80 MB 文本长度上限。不能简单去掉限额再多次完整复制大快照，也不自动降级到明文启动；应与 #2 / #18 的逐表迁移、恢复入口和失败重试统一处理，旧库不删除。本轮未改变 SQLCipher 或迁移逻辑，未做 Android 设备迁移测试。
- **#35 认可风险、保留**：严格 UTF-8 失败即整本 GBK，缺少不支持编码的明确判断。低错误率修复与 UTF-16 无 BOM 推测是启发式，不能保证短书或混合编码正确；后续结合原始来源保留、显式编码 / 预览和导入失败提示处理，不静默重新解释既有书籍。

#36–#40 以本版源码和新回归结案，#33–#35 继续开放，与旧 11 项一起形成 14 项待做；这不是“不需要”，而是数据安全工作尚未完成。两位协助 Agent 的观察均保留原链接和结论，不把部分有误的建议整包照搬。
