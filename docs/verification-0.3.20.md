版本 0.3.20+23，ARM64 版本码 2023；基于 main `784a748`。

## 修复及来源

- 缓慢移动离开半个 Flutter drag slop 时，取消 250ms 静止长按等待；明确接受横滑时再次取消。静止长按仍交给原生文字选择。使用既有手势组件，不新增手势库。
- 按 Readium 起手与松手方向一致性的处理修正反向收手。本项目以识别横滑后的首次非零位移取得初始方向；松手方向相反即撤回。保留已有距离接受逻辑及零速度慢拖，这是 Flutter 适配，不是完整照搬 Readium 的 fling-only 门槛。原收尾曲线及时长公式不变。
- 相邻纸面显式标识 ready / loading / boundary。loading 时等待排版缓存和纸面绑定、绘制，不调用同步跳章；取消、锁定、离开阅读页及过期准备不能提交该次手势。
- 前后章在到达章界前开始预热。与当前页共用同一个分页算法，在每次 TextPainter 测量之间可以让出执行权；每帧至多完成一页，批次达到 2ms 后在下一次测量前让出执行权。普通拖动和收尾暂停预热，等待冷邻页时恢复准备。布局缓存仍最多三章，纸面仍最多三张。
- 参考 Legado TextChapterLayout 的页面准备、取消与逐步排版方法；没有复制其 GPL 代码或移植 Android 原生后台引擎。Flutter 适配在 UI isolate 分帧，整章准备完成后发布缓存。不是 compute 后台 TextPainter，也不是已经实现逐页可进入的原生排版引擎。
- 当前已准备的纸面交接仍提升原有正文子树，保留全屏、设置区、选字、数据与字体配色。

固定版本源码和声明见 [翻页来源](reader-paging-sources.md)。

## 验证边界

单次 TextPainter 测量无法抢占，可能超过 2ms；这个数是批次让出执行权的目标，不是所有帧都在 2ms 内的保证。文本预处理、初次打开当前章以及真正字体 / 尺寸变化时的当前章排版仍可能同步执行。极长邻章首次冷加载会等待整章缓存完成；预热降低触发机会，不等于任意章节都零等待。

本轮自动测试不能证明手机手感已达标，也不能把跨章缺陷认定为此前全书末页卡顿的根因。#70 / #74 保持开放；不改系统刷新率，不清手机数据。诊断日志只加入独立 profile 副本，不进入正式源码或 release 包。
