## 证据与实现

- 新边界回归在原版失败：宽300，向无邻页方向拖120，再反向25，实际位移仍0；修复后反向位移立即25，释放正常提交有效一页。覆盖全书开头 / 末尾两个方向。这是同一次触摸的隐藏位移问题，不能据此归因所有分次末页返回卡顿。
- 新跨原点回归在旧方向判定下失败：左拖100、右拖200、向右释放1000，已显示上一页却撤回；修复后提交上一页。仅反向收手但未越过原点仍撤回，原低速反向回归保留。参考 Legado HorizontalPageDelegate 的跨原点切换方向。
- 新绘制回归在原版失败：纸面外层组件在每次移动时重新创建。改用 Flutter Flow + 绘制通知后，连续拖动及收尾期间保持同一组件树；已有排版 / 绘制计数、预备页面提升及中文字形位置回归继续验证。
- 前后邻章从两个独立的预算改为一个共享队列，轮流推进，输入 / 收尾中暂停备用章，冷加载目标章优先。新增回归检查全局一帧最多一页、无饥饿、暂停 / 必需页优先和失效取消。来源与选择依据见 reader-paging-sources.md。
- 当前章 / 已准备相邻正文来自内存；稳定拖动 / 收尾帧不读取磁盘、重新排正文或启动快照。快速新触摸接管会提交旧页并绑定新远页，仍可能发生首次布局 / 绘制，不能说整个连续手势全程没有创建页面。平移使用保留绘制层；其他淡入 / 仿真仍用原快照路径。进度仅在实际提交后通过已有 SQLite 队列保存，没有全书库 JSON 编码。

## 候选2：实测 Android 主线程阻塞与官方修复适配

原 release 系统 Perfetto 在自动回翻协议中记录到一次 `flutter/processtext` 原生消息处理耗时 **50.829ms**，17次共53.400ms，运行于应用 Android 主线程。它是处理区间的墙钟时间，不是51ms纯 CPU；也未证明它对应用户每次末页卡顿。每次新建 SelectableText 的 EditableText 会查询系统选字操作，Flutter 官方 PR #189823 对 PackageManager Binder 查询及标签磁盘读取作了后台 TaskQueue 修复。本机实际 embedding jar 经 javap 核验，仍使用主线程通道，不含该修复。

第一候选同协议记录17次，峰值0.403ms、总3.497ms，仍在主线程。这个单轮差异可能受系统缓存 / Binder 等状态影响，不能归功于 Flow，也不据此宣称阻塞消失。候选2直接复用现有引擎的解析器 / 插件，仅将查询放入框架后台串行队列，其余动作回 Android 主线程；不升级 Flutter、重写选字插件或改变正文。

候选2原生 release 编译成功，包 `outputs/releases/shuye-0.3.20-paging-candidate2-arm64.apk`，32,696,374 字节，比原包增加8,688字节。SHA256 `f9f9b5489108522fba07a2659c4a3fd0cf122c4686af4c648c0fc130d70e92b4`，相同包名、0.3.20 / 2023及正式证书，v2签名校验通过。`adb install -r` 成功后再次拉取 base.apk，实际安装哈希一致。Dart代码不变，沿用本轮151项通过的结果；原生改动另以编译、线程轨迹与实际选字流程验证。

系统 FrameTimeline 此设备轨迹只提供 SurfaceFlinger / 系统栏，没有书叶 SurfaceView 的逐帧数据，因此不能用其中的零 jank 认定应用零掉帧。系统轨迹只用于定位，不在人工手感验收期间运行。候选2的线程迁移及人工结果补记在下文；尚未发布新正式版本。
