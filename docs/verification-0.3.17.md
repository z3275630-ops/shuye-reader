# 0.3.17 真机翻页交接验证 · 2026-10-09

版本 `0.3.17+20`，ARM64 版本码 2020，基于 main
`dc6e40d6abae472c3d8a2755f63b8b611c659f9e`。用户反馈 0.3.16 的翻页仍有顿挫，要求继续定位和修复。

## 定位与改动

- 在授权 PJZ110 手机上测量 Flutter profile 的逐帧构建、绘制时间，并在独立测试副本记录分页、拖动、提交和纸面绘制事件。日志只含事件名、时间和数量，不含正文；临时测量代码不进入正式包。
- 0.3.16 已经提前排版相邻页，但当前正文和预览页属于不同的子树；落定时又创建当前页的 SelectableText。新增回归在旧版失败，确认预览与提交后的 RenderEditable 不是同一个对象。真机提交事件对应的样本中，构建最高 16.166ms。
- 现在当前、前后页使用同一个纸面结构，并以具体页标识保留渲染子树。进入页落定时直接成为当前页，不再创建第二份正文；交接帧把已进入纸面放在零位，避免重复显示它。
- 只保留当前及前后页，前后翻都能复用已准备好的段落；离屏页不接收输入、不暴露语义。当前页恢复选字、复制、摘录等操作；双页两栏共用相同处理。
- 保留 0.3.15 的字体配色、页边距、正文高度、源 offset、进度串行保存、手指释放速度衔接、取消和锁定行为。未改字体、图片、依赖或数据库结构。
- 第一轮真实手指复测仍反馈卡顿，进一步明确为“松手后，滑动或停下不自然”。因此把手指松手后的固定时长 Hermite 曲线试用 Flutter PageView 的默认 ScrollSpringSimulation，但第二轮用户反馈滑动太慢、跟手不足，连续翻页卡顿，因此拒绝默认参数。最终候选采用更快的临界阻尼参数（mass .5 / stiffness 1800 / damping 60）；沿用释放速度，按剩余距离收尾，快滑到页边即停止，不越界回弹。点击翻页、淡入和仿真继续保留原路径。

## 第一轮真实手指复测

统一纸面后的测试副本记录 685 帧、51 次手势、39 次提交。构建最大 4.254ms、绘制最大 5.564ms；max(build, raster) 没有超过 8.33ms 的帧，但存在一次 49.178ms 的 vsync 等待，不能宣称没有显示顿挫。

按拖动和收尾事件划分，155 个拖动帧间隔、381 个收尾帧间隔均为约 16.6ms，没有约 8.3ms 的间隔。设备当时允许书叶的应用刷新率上限为 60Hz，虽然屏幕支持 120Hz；本轮不改系统设置，也没有将刷新率上限直接认定为用户反馈的根因。用户明确表示松手后的运动不自然，这是追加收尾修复的依据。

此样本没有分页事件，不能据此排除其他书籍或极长章节的分页开销。第二轮用户明确反馈收尾太慢且连续翻页卡顿，该默认模型不采用。手机日志环形缓冲覆盖了较早操作，仅剩 62 帧、2 次手势，不把这段残留日志当作完整复测。

## 第三轮真实手指复测及结论

加快后的候选通过电脑实时保存 1744 帧、122 次手势、102 次 commitStart 事件。构建 p95 3.843ms / 最大 18.261ms，绘制 p95 2.957ms / 最大 11.906ms；max(build, raster) 超过 16.67ms 为 1 帧，超过 8.33ms 为 12 帧。总帧跨度另有 7 帧超过 16.67ms；这些计数均不作为显示掉帧率。相邻页 paint 事件最高 11.213ms，layout 最高 6.896ms；静态相邻页之前只离屏排版，没有提前绘制。

用户反馈“快了不少，连续滑动没有那么卡，但仍偶发卡顿，只有快、不够丝滑”，随后明确要求采用成熟阅读器的实现。故本版只记录阶段改善，不作为手感通过；下一版移植 Readium 的分页减速 / 时长公式，采用整页绘制记录和结束旧收尾再接新手势的处理，见 0.3.18 验证。
